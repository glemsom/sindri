# Request metrics and stable replay

Turn usage, the session document, JSON outcomes and `sessions show` carry observed
input/output/total/reasoning/cached-input counts, cache read/write token counts,
request milliseconds and client/native compaction counts. Missing fields mean
unknown, not zero. Explicit provider zeroes remain zero. Aggregates sum available
observations; they are not complete totals when a constituent metric is absent.
Cache reads retain the existing `cached_input` name as well as `cache_read`;
these are aliases, not additive spend. Request milliseconds measure the successful
stream through completion, including a rejected-handle recovery attempt, but not
tool execution. Successful compaction usage and latency are charged with the
following successful turn. Failed requests and failed compactions have no usage
report; no invented spend is assigned to them. A compaction status event describes
both native and client reduction without exposing the returned material.

The locked adapter exposes cached-input and cache-creation token counts; no raw
response, encrypted reasoning, compaction window or credential is added to metrics.
No endpoint, model capacity, cache eligibility or price is inferred from these counts.
Native compaction reads only numeric usage fields from its explicit response.

## Deterministic verification

Run inside the workspace with Devbox:

```sh
devbox run -- cargo test --workspace -- --test-threads=1
devbox run -- cargo test -p sindri-core --test eval_wire -- --ignored --test-threads=1
devbox run -- cargo test -p sindri-core --test eval_redaction -- --ignored --test-threads=1
devbox run -- cargo clippy --workspace --all-targets -- -D warnings
devbox run -- cargo fmt --all -- --check
```

Captured multi-prompt launch tests compare unchanged instructions, tools (including
names, descriptions, schemas and order), and earlier serialized input. HTTP request
IDs generated by transport are outside these body comparisons. Legitimate target
changes and compaction establish different boundaries. This is prefix-compatibility
evidence, not a live cache-hit or provider-compatibility claim.

## Optional authorized live comparison

Do not run this as CI or without explicit authorization and a spend ceiling. Select
one verified endpoint, served model, storage policy and identical tool/instruction
catalog. Compare full replay with client compaction, verified native compaction,
and explicitly opted-in continuation where supported. Follow the capability and
storage constraints in `native-compaction.md` and `responses-continuation.md`; never
send unsupported fields to Copilot/custom endpoints.

Use follow-ups requiring an exact tool-discovered identifier absent from the final
answer, plus a completed write that must not be repeated. Record correctness,
observed token counts (cache read/write and reasoning where exposed), measured
request/whole-run latency and total spend using the served model's verified prices.
Include summarization/compaction requests in spend. Report unknown prices or counts
as unknown. Hold workload and configuration fixed, repeat trials and state sample
sizes and cache-warming conditions; require no nondeterministic savings threshold.
Keep only aggregate numeric observations and non-sensitive configuration labels:
never retain credentials, captured request bodies or opaque artifacts for measurement.
No live comparison was performed for this implementation.
