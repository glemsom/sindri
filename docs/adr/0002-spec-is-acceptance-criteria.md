# The spec is acceptance criteria, not a plan

`docs/SPEC.md` says what Sindri must be capable of. It does not describe order of work, and it
is not edited to make a build look finished: a criterion changes when it was wrong, never when
it was inconvenient. A gap in it is closed where it is written, or by an ADR when the answer is
a design decision — never left as a footnote for a later reader to reconcile.

The layers: **spec** = what must be true, **`docs/adr/`** = why it is built this way,
**`GLOSSARY.md`** = what the words mean, **milestones and tickets** = when.
