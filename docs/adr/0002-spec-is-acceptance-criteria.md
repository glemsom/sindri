# The spec is acceptance criteria, not a plan

`docs/SPEC.md` describes what Sindri must be capable of. It does not describe order of
work, and it is not edited to match what was built. Its internal contradictions live in
one appendix listing every open question, so that a question is either answered by an
ADR or still visibly open — never quietly resolved by whoever was typing.

The layers: **spec** = what must be true, **`docs/adr/`** = why it is built this way,
**`GLOSSARY.md`** = what the words mean, **milestones and tickets** = when.
